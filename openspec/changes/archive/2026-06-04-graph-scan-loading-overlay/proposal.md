# 提案: graph-scan-loading-overlay

> **变更**: graph-scan-loading-overlay
> **日期**: 2026-06-03
> **状态**: 提案中

---

## 问题

### 背景

当前 Dashboard 界面上提供了一个 "Scan" 按钮，用于触发服务端依赖分析（`POST /api/analyze`）。分析过程通过 Rust 二进制 `dcr-aggregate` 或 Node.js 回退执行 dependency-cruiser 扫描，对于大型项目可能需要数秒至数十秒。

### 问题描述

扫描期间的交互体验存在以下问题：

1. **缺乏全屏反馈**：扫描期间仅 Scan 按钮自身变为 disabled 状态并显示旋转图标，用户无法清晰感知当前正处于不可交互的扫描阶段。
2. **操作未被阻止**：扫描期间用户仍然可以点击 Refresh 按钮、切换导航标签、拖动画布、选择节点等。这些操作在扫描未完成时是无意义的，甚至可能因竞态条件导致状态不一致。
3. **扫描完成后无自动刷新**：扫描成功完成后，当前图数据不会自动更新。用户必须手动点击 Refresh 按钮才能看到新的分析结果。这与用户期望的 "扫描即刷新" 工作流不符。
4. **错误反馈不够醒目**：扫描失败的错误信息以小字内联显示在 action bar 下方，容易被用户忽略。

### 目标

1. 扫描期间显示全屏加载遮罩层，阻止所有用户交互
2. 遮罩层中提供明确的状态反馈（进度条、状态文字）
3. 扫描完成后自动刷新图数据
4. 扫描失败时在遮罩层中醒目标示错误信息

---

## 方案

### 方案描述

新增 `ScanOverlay` 全屏遮罩层组件，在扫描期间覆盖整个应用界面（包括顶部导航），阻止所有点击/滚动/键盘交互。遮罩层包含：

- **居中卡片**：放置在屏幕中央，显示扫描状态图标（旋转动画）、本地化状态文字（"扫描中..." / 当前进度描述）
- **不确定进度条**：使用 CSS 动画的无限进度条，表示扫描正在进行
- **成功自动关闭**：扫描完成后自动关闭遮罩层，并触发 `refresh()` 重新加载图数据
- **失败状态显示**：扫描失败时遮罩层显示错误详情和 "关闭" 按钮，由用户手动关闭

### 交互流程

```
用户点击 Scan 按钮
  → ScanOverlay 全屏显示，所有交互被阻断
  → POST /api/analyze 执行
  → 成功：遮罩层关闭，自动调用 refresh() → fetchGraph()
  → 失败：遮罩层显示错误信息，用户点击关闭
```

### 变更要点

1. **新增 `ScanOverlay` 组件**：React 全屏遮罩层，使用 `position: fixed; inset: 0; z-index: 9999` 覆盖所有内容
2. **修改 `App.tsx`**：`scanning` 为 true 时渲染 `ScanOverlay`；`handleScan` 成功后调用 `refresh()`
3. **修改 `GraphViewLayout.tsx`**：Scan 按钮的行为保持不变，但扫描效果由全屏遮罩层接管
4. **新增 i18n 词条**：扫描状态文本和错误文本的本地化支持
5. **新增 CSS**：进度条动画 keyframes

## 变更范围

### 范围内

- `ScanOverlay` 全屏遮罩层组件的创建和样式
- 不确定进度条的 CSS 动画实现
- `App.tsx` 中 `handleScan` 成功后调用 `refresh()` 的逻辑修改
- `App.tsx` 中 `scanning` 状态绑定 `ScanOverlay` 渲染
- `GraphViewLayout.tsx` 中扫描按钮文案调整（扫描期间显示 "扫描中..."）
- `en.ts` / `zh-CN.ts` 新增扫描状态相关的 i18n 词条
- `main.css` 新增进度条动画 keyframes

### 不在范围内

- `POST /api/analyze` 服务端接口的修改（接口行为不变）
- WebSocket 或 SSE 推送扫描进度的支持（保持简单请求-响应模式）
- 扫描过程的取消/中断功能
- 扫描进度分阶段显示（仅使用不确定进度条）
- Graph/Report/Metrics 视图之外的其他视图的扫描支持
- 文件上传模式下的加载遮罩（仅针对 POST /api/analyze）

## 风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 全屏遮罩层 z-index 不够高，被其他元素覆盖 | 中：遮罩层不能完全阻止交互 | 低 | 使用 `z-index: 9999` 并确保 `ScanOverlay` 在 React 组件树的最外层渲染（`App` 根级别），在所有 Provider 之后。添加 E2E 测试验证遮罩层为最高层级。 |
| 扫描快速完成（< 300ms）时遮罩层闪烁 | 低：短暂闪烁影响视觉体验 | 中 | 设置最小显示时间逻辑（如至少显示 500ms），避免扫描瞬间完成时遮罩层闪烁。 |
| 进度条动画在低端设备上卡顿 | 低：进度条动画不平滑 | 低 | 使用 CSS `@keyframes` 动画而非 JS 驱动动画，利用 GPU 合成层（`transform: translateX()`）确保性能。 |
| 遮罩层阻止了扫描完成后的自动 refresh 的 fetch 调用 | 高：refresh 无法正常执行 | 低 | 遮罩层仅阻止用户输入事件（pointer-events / 事件监听），不影响 JavaScript 发起的 fetch 调用。将 `refresh()` 调用放在 `finally` 块中或 `setScanning(false)` 之后执行。 |
